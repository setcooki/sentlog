# ADR 0004 — AASIST-L for liveness from Phase 1, not rule-based

**Status:** Accepted
**Date:** 2026-05-22
**Spec reference:** [§1.7](../technical-specification.md#1-architectural-decisions)

## Context

The whitepaper's MVP plan originally called for a rule-based liveness
stub in early phases, with a "real" model arriving later. Research
into the state of the art (ASVspoof 2024/2025, AASIST literature)
showed that:

- AASIST-L (Jung et al., ICASSP 2022, [arXiv:2110.01200](https://arxiv.org/abs/2110.01200))
  is the small variant of the AASIST graph-attention anti-spoofing
  architecture: **~85K parameters, real-time on CPU, ~1% EER on
  ASVspoof 2019-LA closed-set.**
- It is the architecture that matches the profile claimed in early
  drafts ("98%+ accuracy on edge devices in tens of ms").
- The implementation effort for AASIST-L is comparable to a
  rule-based liveness stub.
- Shipping rule-based first means a *worse* signal during the first
  phases of corpus collection, which is exactly when we'd want a
  better one.

## Decision

**Ship AASIST-L for liveness from Phase 1**, not a rule-based
placeholder. Use the community-published checkpoint where licensing
permits (see open Phase 0 gate below). If licensing blocks bundling,
fall back to a rule-based stub *only* in Phase 1, and train AASIST-L
from scratch on ASVspoof eval data in parallel — adding roughly 4
weeks to liveness maturity.

The liveness output is exposed as a `Liveness` struct with:
- `score` — overall liveness 0..1
- `replay_risk` — risk from replay-attack signals
- `synthetic_risk` — risk from TTS / voice-cloning signals

Per-attack sub-scores let integrators tune to their threat model and
let us publish honest per-attack-class benchmarks rather than a single
headline number.

## Consequences

**Enabled:**

- Phase 1 ships with a real liveness model, not a stub. The corpus we
  collect during Phases 1–5 has labels generated by something
  meaningful.
- Per-attack-class reporting is honest and is what we plan to publish
  in Phase 8.
- The architecture is small enough that it doesn't move the Android
  benchmark gate threshold.

**Constrained:**

- Liveness against modern voice cloning (ElevenLabs, OpenAI, XTTS
  class) sits at 60–80% clean and 55–70% over telephony, per the
  research. Sentlog is positioned as a *risk signal*, not an
  authenticator (see ADR 0006).
- The pretrained-weight licence is a Phase 0 gate. Verifying this is
  blocking.

## Open Phase 0 gate

The AASIST-L pretrained-weight licence must be verified before any
checkpoint is bundled. If non-permissive, Phase 1 ships rule-based
liveness and a training-from-scratch pipeline runs in parallel;
reliable liveness slips ~4 weeks. Tracked in
[docs/rollout-plan.md §5.2](../rollout-plan.md#52-phase-0-engineering-gates).
